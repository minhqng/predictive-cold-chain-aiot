## Why each candidate fails, in full

### `C1-fan-obstruction` - partially block the hot-side fan -> REJECTED_BY_INSTRUCTION

docs/05A §20 A-W11-04 forbids inventing an unsafe fan obstruction; it also stalls the fan, which is a fault in a different class and changes the safety posture

### `C2-heat-base-fouling` - add a controlled thermal resistance at the hot interface (gasket/dust) -> NO-GO

physically alters the frozen hardware configuration, is not quantified without a hot-base probe, and is only partly reversible; the H8 limit table exists to keep the hot path bounded and this pushes an unmeasured variable into it

### `C3-probe-displacement` - move or re-seat a probe to fake a changed reading -> NO-GO

this is a sensor fault, not a thermal-effectiveness fault, and it produces exactly the contamination the 2026-11-02 PROBE_IDENTIFICATION session is excluded for: a hand on a probe. The label would be untrustworthy by construction

### `C4-door_left_cracked` - hold the door at a fixed small opening -> RECLASSIFIED

a steady added load with unchanged heat transfer is a load disturbance, which is S2's mechanism; labelling it S3 would put two names on one physical effect and destroy the contrast Member B trains on

### `C5-reduced-drive-in-software` - cap duty or current so less power reaches the stack -> RECLASSIFIED

reducing the drive is an actuation-response change, which is S4; the electrical response would NOT remain plausible, so it fails S3's first condition by definition

### `C6-raise-ambient` - warm the room or the bench environment -> NO-GO

not controllable or repeatable at 1 Hz within a supervised session, and the ambient path is already documented as not the plant (docs/05A §16.3 ambient path is only a candidate); it also changes the baseline every paired run depends on

## What would change the verdict

install a cold-plate probe and a hot-base probe, resolve hot_base_max_c and cold_plate_min_c in the limit table, qualify the electrical columns with a real producer status, and then collect at least 2 healthy and 4 degraded captures

| `R4-matched-healthy-baseline` | the same hardware configuration id, firmware version, sensor ROMs, physical positions and duty as the degraded run, immediately before or after it | effectiveness is a ratio against the healthy state; without a matched pair the degradation is indistinguishable from drift or a different box |
| `R5-repetition-count` | at least 2 healthy and 4 degraded captures, each a separate session with its own boot_id, and the timing of each edge from an operator timer | a degraded label needs a distribution to be degraded relative to, and one boot's segments are not independent runs |
| `R6-confounders-and-interventions` | ambient temperature and humidity, door state with its per-boot attestation, fan readback, any manual intervention, and the end reason | the S2 door disturbance and an S4 refusal both move chamber air; if they are not recorded they silently contaminate the S3 label |
| `R7-not-done-declaration` | what was deliberately not attempted (shorted branch, bypassed fuse, damaged TEC, obstructed fan) and why | docs/05A §20 A-W11-01 forbids those methods; the absence of a record that they were refused is indistinguishable from having quietly used one |
