# S4 protocol v1 - safe actuation-response fault, three lanes kept apart

Requirement: `docs/05A` §20 A-W11-01 / A-W11-02. Generated by `build_w11_artifacts.py` from `firmware/tools/cg_w11_s4.py` (w11-s4-v1) and `firmware/tools/cg_s4_refusal.py` (s4-refusal-v1); build stamp 2026-11-02T00:00:00Z is HOST_BUILD_CONSTANT_NOT_A_DEVICE_TIME.

**Status: IMPLEMENTED / HOST_VERIFIED; physical leg NEED_USER_ACTION**

## 1. Method

create the fault in the safe layer only: the device or harness intentionally refuses or blocks actuation while keeping the protocol visible. Never short a branch, never bypass the fuse, never damage the TEC (docs/05A §20 A-W11-01).

## 2. The four evidence lanes

| lane | read from |
|---|---|
| `INTENT` | the issued command and its ACK payload (desired_*) |
| `APPLIED` | pwm_applied_permille / applied_cooling read from a device frame |
| `ELECTRICAL` | current_a with current_status=OK - no-active-response |
| `THERMAL` | chamber-air probes showing non-response |

## 3. Expected signature and what it proves

* `intent`: desired_cooling=ON, desired_duty_permille>0
* `applied`: pwm_applied_permille=0, or ACK SAFETY_BLOCKED with applied OFF
* `electrical`: current_a below the no-response floor with status OK
* `thermal`: no chamber-air movement beyond the noise floor from cg_w10_pairing
* `proves`: command != electrical effect

## 4. Promotion rules the validator enforces

* forbidden lane sources: `['INFERRED_FROM_INTENT']`
* refusal statuses that may never carry an applied action: `['REJECTED', 'EXPIRED', 'SAFETY_BLOCKED', 'INVALID_STATE', 'OUT_OF_RANGE']`
* non-reapplication statuses: `['DUPLICATE_CANONICAL']` (docs/02 §30.1 forbids a replay applying again)
* rule: intent may never populate the applied, electrical or thermal lane; a lane's source must be a device frame, a device ACK payload, an explicit host-fixture label, or an explicit absence
* electrical floors used so the two S4 tools cannot disagree: no-response below 0.05 A, residual above 0.5 A (PZEM-017 LSB is 0.01 A; the floors match cg_command_trace so the two tools cannot disagree about what 'drawing current' means)

## 5. Hazard this protocol exists to catch

a harness that reports SAFETY_BLOCKED while the output is actually energised is the failure S4 must catch. The three-lane split plus the promotion rule is what catches it: the block verdict alone would look perfectly safe.

## 9. Capture recipe (what closes S4)

* status **NEED_USER_ACTION**, 4 repetitions, 1 Hz device telemetry, command lines interleaved in the same capture, planned capture 240 s

### Prerequisites

* a transport and an issuer exist (Member C), or a bench harness path that is explicitly labelled as not-a-transport
* operator at the bench, TEC current path and fuse posture confirmed
* the qualified electrical lane must exist before the run: current_status must be emitted and recorded OK, not empty

### Per repetition

1. boot, open capture before ARM, record boot_id
2. enter the safe refusal mode (test-mode block, not a physical fault)
3. issue the ON request with the planned duty and record the ACK verdict
4. hold 60 s and capture applied duty + current + chamber air
5. exit refusal, re-issue, capture the responding leg as the contrast
6. record the operator timer and any intervention

### Downstream unlocks

* Member B's S4 label for diagnosis training
* Member D's evidence that a blocked verdict does not energise the output

## 10. Not done, on purpose


* no shorted branch, no bypassed fuse, no damaged TEC, no invented fan obstruction
* no command was simulated as received by a device
