## 2. Pass-criteria walk

| Criterion | Result |
|---|---|
| a door reading is never treated as a door state without attestation | **met** — an unattested segment is named `CLOSED_AS_REPORTED` / `OPEN_AS_REPORTED`, never `CLOSED` / `OPEN`, and carries `state_semantics=REPORTED_BY_FRAME_ONLY_NOT_PHYSICALLY_NAMED`; `frames_alone_can_name_door_state() = false`; the inversion rests on `docs/01` §8.1/§8.2 and the complementary mapping table in `cg_w10_door.MAPPING_BY_POLARITY`, while its code-level proof is labelled `UNCITABLE_UNTRACKED_SOURCE` (see `evidence/A/W09/run-registry.json`) instead of being quoted as citable; attestation is per boot and a mismatch is an error |
| `UNKNOWN` never folds into `CLOSED` | **met** — the 17 unknown frames form their own segment (`STARTUP_POLARITY_PENDING`); `unknown_is_not_closed: true` in the report and asserted by tests |
| an incident window is not a pilot disturbance | **met** — classification requires physical source + per-boot attestation + operator-controlled timing + protocol id + a rise above the measured floor; each unmet condition is returned as a named reason, not a silence |
| chamber-air statistics exclude the TEC hot side | **met** — T2 is reported separately in the noise profile and never averaged into the chamber mean |
| no fixture is presented as a disturbance | **met** — every event carries `is_physical_measurement`; `pilot_status()` sets it false and the validator fails if the artifacts ever hide the gap |
| the horizon choice belongs to B, the critical threshold belongs to D | **met** — `member_b_decision_inputs_not_supplied_by_member_a` names them and nothing here supplies them |
| fail closed on a missing field | **met** — a missing `door_cycles` yields `aligned: null`, not `aligned: true`; a missing polarity field yields `UNKNOWN`, not CLOSED |

## 3. What closes S2

1. The operator runs one repetition of `S2-protocol-v1.md` §3 on a supervised,
   energized rig and commits the capture to the repository (a tracked file,
   hash-pinnable).
2. The per-boot `DOOR NEAR_LOW <token>` attestation is recorded for **that**
   boot_id, with the lid-seated CLOSED reading taken after it.
3. `door_cycles` and `door_raw` reach the exported frames (the derived W04 CSV
   does not carry them), so the MC-38 cross-check can close.
4. ≥4-6 such disturbances with paired same-configuration S1 baselines exist;
   then the tolerance estimator returns a number instead of `null`, and the
   door→critical distribution becomes computable once D freezes the threshold.

Until then `valid_pilot_disturbances_available: 0` is the published result, and
`run_all_checks_w10.py` ends with that reminder.
