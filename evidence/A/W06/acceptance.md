## 3. Defects found and fixed while building W06

1. **`split_line()` never assigned `*verb` on the two-token path** in the
   delivered W04 parser, so `ARM`/`CLEAR`/`START`/`RUN`/`PHASE` compared
   uninitialized stack memory — undefined behaviour that no test had ever
   exercised. Found by the first host parse of those verbs in this slice; fixed,
   pinned by a scenario and by a static check, and a mutation removes the fix
   again to prove both fail.
2. **Five checker assertions could not fail** when their mutation tests were
   first run: the unsynchronized guard, the duplicate branch and the
   overflow-refusal branch each passed on a string that survived being made dead
   code; `nvs` was checked in the wrong file; and the ACK status-name function was
   only checked for containing the seven names, not for containing **only** them
   (a `VERIFIED` status would have passed). All five rewritten to bind the live
   construct, then re-proved.
3. **The demo trace initially reported a phantom replay** because two unrelated
   fixtures shared a `command_id`, which is the aggregation key. Distinct ids
   restored a truthful demo; the lesson is recorded, since a trace keyed on
   command identity must not merge unrelated submissions.
4. **Serial schema 3 vs command schema 1 collision risk**: the ACK line states
   `schema=1` for the docs/02 envelope while the telemetry line says `schema=3`;
   a test asserts the ACK never carries the serial number, so the two streams
   cannot be conflated by a reader or a parser.

## 4. Physical actions still owed

1. Time synchronization or a contract amendment, so `expires_at` becomes
   evaluable on the device (C's NTP/SNTP path, or a documented relative-expiry
   amendment). Until then **no remote command can be accepted at all** — which is
   safe, but should be a decided state, not a permanent accident.
2. A transport decision with C (no network stack exists in firmware and the W04
   checker proves it; adding one is its own safety-reviewed slice).
3. Authorized flash of this image, with the backup/restore prerequisites from the
   W05 record, then the reset-with-command power-cycle log.
4. Supervised energized session for `ELECTRICAL_VERIFIED`/`THERMAL_VERIFIED`.
5. W05's ≥30-minute telemetry capture remains open, unchanged by this slice.

## 7. Dated corrections to earlier records (2026-11-02)

The W04 and W05 dossiers are deliberately left byte-identical to the revision
that was reviewed, so these errors are corrected here instead of in place.

1. **Six operating limits, not seven.** `evidence/A/W04/README.md`,
   `evidence/A/W04/acceptance.md`, `evidence/A/W05/README.md` and
   `evidence/A/W05/acceptance.md` each say "seven". `CG_LIMIT_COUNT` is 6:
   `current_max_a`, `voltage_max_v`, `voltage_min_v`, `hot_side_max_c`,
   `duty_max_permille`, `on_time_max_ms` (`firmware/main/cg_tec_limits.h:23-31`).
   The fail-closed conclusion is unchanged — all six ship `UNRESOLVED` — so this
   is a wording defect, not a safety one.
2. **The W05 serial-line budget is superseded by schema 3.** W05 published 1873
   bytes typical, 2098 constructed worst case, 2560 shipped
   (`CG_TELEMETRY_LINE_MAX` then). The command and desired-state fields raise the
   measured worst case to 2256 bytes against a raised buffer of 3072
   (harness: `w06_worst_case_len=2256 budget=3072`). The new ACK line has its own
   measured budget: 558 worst against `CG_COMMAND_ACK_LINE_MAX 640`. Any band
   estimate built on the W05 frame size understates W06 by 383 bytes worst case
   and must be recomputed from these numbers.
3. **Checked and *not* in error:** W05 §6 claimed thirteen files of the W04 pin
   list differ on its own branch. Re-counted from the delivered W05 head
   (`f249b77`) that number is correct — 13 — and the 16 above is W05's 13 plus
   `cg_log.h`, `cg_tec_command.c` and `cg_tec_command.h`, which only W06 changed.

## 8. Review record

Two independent read-only reviews were run on this slice before delivery. Their
findings, and what each produced:

| Finding | Disposition |
|---|---|
| Receive-time TTL was being used as a freshness proof | Accepted. Rejected outright: expiry is evaluated only against a synchronized clock, otherwise `SAFETY_BLOCKED / EPOCH_UNSYNCHRONIZED` with `expiry_evaluable=0`. A static check fails the build if a `created_at`-substitute expression appears. |
| The local console bridge could be mistaken for the network command contract | Accepted. `CMDTEST` is stamped `source=LOCAL_CONSOLE` with `command_id_form=TEST_TOKEN` and a `LOCAL_TEST` controller id, carries no timestamps, can never reach `ACCEPTED`, and cannot advance desired state; `handoff-w06.md` states the distinction for C. |
| Numeric fields parsed without overflow guards | Accepted. All four numeric call sites now use an overflow-checked unsigned parser that refuses rather than wraps. |
| ACK line size was assumed, not measured | Accepted. Worst-case scenario added and pinned at 558 bytes under a 640-byte budget. |
| Replay attribution could cross a reset | Accepted. The trace attributes events to a `boot_id` and refuses to promote across one; `reapplied=1` is reported as a defect, never as success. |
| Docs cited `§32.2` at the wrong line range and the handoff claimed verbatim field names | Accepted. Anchors corrected, and the renames (`created_at` → `created_at_ms`, `action.duty` 0..1 → `action_duty_permille`) are now disclosed as conversions instead of described as copies. |
| Five checker assertions could not fail | Accepted and re-proved: each mutation now removes the live construct, and one must-not-fire control asserts the guard is real. |
| Latent `split_line()` UB in the delivered W04 parser | Accepted as a W04 defect, fixed here (§3.1), because the fix is required for W06 parsing to mean anything. |

Re-checked directly against the delivered tree rather than taken from the review
notes: `cg_tec_start` has exactly one call site (`cg_commission.c:255`, the
console `START` handler) and none in `cg_command.c`; `grep` for `nvs`,
`flash_write`, `ledc_set_duty` and `gpio_set_level` in the command path returns
nothing; the harness reports `36/36` scenarios and the checker reports `93
checks`; `evidence/A/W06/build/22-source-hashes.txt` verifies 0 mismatches
against `firmware/`, which is what makes the §6 image claim mean anything.

A third read-only pass was dispatched against this post-fix revision as the
branch was being delivered. It cannot change a status in §1: A-W06-05 and the
physical half of A-W06-06 stay open because no transport, issuer or authorized
energized session exists, not because of a code finding. Anything it reports is
handled as a follow-up commit on this branch, with the finding recorded here.
