# W14 spatial statistics (A-W14-03)

Generated by `evidence/A/W14/build_w14_artifacts.py` from committed captures. Nothing was measured for this report: no flash, no energized stage, no probe moved, and every figure below is host analysis of rows already in the repository.

## Verdict

- independent thermal sessions on disk: **1** (`boot_id` 56044b74), each phase block labelled from its own capture
- gradient distribution: **NOT_COMPUTABLE_AS_DISTRIBUTION** - a distribution needs 3 independent sessions, so what is published instead is one session's per-sample series, labelled `SINGLE_SESSION_OBSERVATION`
- disturbance-specific spatial response: **NOT_COMPUTABLE**
- max pairwise air difference in the driven block: **1.126 C**, against **18.938 C** between an air probe and the hot-side surface

## What one session can and cannot say

It can say how far apart the three chamber-air positions sat from each other while the bridge was driven, and how far the hot-side surface sat from them. It cannot say what the run-to-run spread of those quantities is, because one boot of one session carries no repetition; calling its sample dispersion a distribution would be the exact defect this deliverable exists to avoid.

## Disturbance-specific response

**NOT_COMPUTABLE**. no door-open transition exists in the capture: the field is never OPEN, so there is no applied disturbance whose spatial response could be measured. Estimating one would be inventing a physical event.

Re-derived from the capture rather than quoted from a document:

- rows: `957`
- `door_open` token tally: `{'0': 940, 'UNKNOWN': 17}`
- rows that are OPEN: `0`
- rows whose door state is not knowable: `17`
- confirmed closed: `940`

What would make it computable: a supervised session that opens the door to a recorded extent and holds it for a bounded window, with door_polarity CONFIRMED on the open rows, repeated at least the required number of times

## Data limits this report lives inside

- one `boot_id` (56044b74) across 957 rows, so baseline, cooling and recovery are segments of one session, not three runs
- `current_status`/`voltage_status` are empty in every row and `power_w`/`energy_wh` have no status column, so no electrical figure is status-checked
- `device_ms` is per-boot; host wall-clock is not device time
- the `#CG H8S schema=3` frames carry no sensor ROM ids, so a channel is a slot name, not a proven physical probe
- the 2026-11-02 touch session is classed `PROBE_IDENTIFICATION` and is excluded from every number above
