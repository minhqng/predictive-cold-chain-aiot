## 2. What the producer actually publishes

The PZEM-017 is read as six input registers (`firmware/tools/cg_modbus.py`: 0x0000 voltage, 0x0001 current, 0x0002..0x0003 power, 0x0004..0x0005 energy) with the 50 A shunt profile in holding register 0x0003. The device stamps each of voltage, current and power with its own status token and an age; **energy gets a value and nothing else** - no `energy_wh_status`, no age token, in any of the 957 committed raw frames. Power factor and frequency (input 0x0006/0x0007) are not read by this firmware at all.

Reading rules that matter for this table:

* **Producer read failures are stamped, not silent.** In the H8 raw sessions 16 frames carry `current_a_status=IO_ERROR` with an **empty value cell** and an age token of `-1`: the frame still exists, so the correct reading is 'no sample', never 'zero current'. Per source: H8-A-180s 13; H8-B-420s 1; H8-E-1800s 2,
* **Host-side poll failures are recorded explicitly too.** The W03 capture is the other family: 7 of 601 rows are `quality=INVALID` with `physical_fail=1` (`received=29` six times, `received=28` once) and empty value cells. Those are missing-sample evidence, and they are why `frames_without_any_electrical_value` is 7 there rather than 0.
* **The production fail-closed build publishes no electrical value at all**: 62/62 frames label the cells `INVALID`/`NO_DATA` with the value empty. That is a declared absence by design, not a lost sample, and it is the reason a zero from the production build must never be read as a measurement.
* `rx_len=25` is a good poll in the **device-side** trace (~86-111 ms round trip, 8 echo + 17 response). The W03 host collector counts its own received length (28-29), so a byte-length threshold must never be shared between the two collectors.
* `rx_len=0` with `class=NO_RESPONSE` while the 12 V supply is off is the **expected** behaviour of an unpowered meter, not a failed MAX3485; it must not be counted as a transceiver defect.
* `ECHO_ONLY` (rx_len=8) is a retried poll: the H7 60 % diagnostic runs record exactly one each and the stage continued after the retry.
* The committed 600 s CSV has **no failed-poll signature at all** - a failed poll simply never became a row, and the rows that exist carry empty status cells. So 'no row' and 'a row with no value' and 'a row that says IO_ERROR' are three different statements, and only the second and third are visible in this dataset.

### Clock semantics (which clock is the sample time)

* authoritative device time: **device_ms within boot_id + seq (docs/01 18.3)**;
* docs/01 18.5: record uptime and sequence; do not manufacture false timestamp precision;
* a TTL measured on arrival does not establish a command's original age; unverifiable absolute expiry fails closed;
* docs/01 18.4: historical validity != control freshness;
* no source in this dossier uses a host wall-clock stamp as the sample time, and opening the COM port starts a new `boot_id`, so a segment of one boot is never filed as an independent run.

Documented latency behaviour, from these captures:

* the first sample after START still holds the pre-run registers (current 0.00 with duty nonzero) - one frame per driven block;
* the first poll after outputs go off returns the **last loaded current** (7.11-7.15 A in the H8 sessions, one frame period after the last driven frame), and the poll ~1 s later reads the unwinding value (0.41-3.57 A) or 0;
* steady OFF current never exceeded **0.02 A** - one current LSB - which is the meter's own noise floor, well under the bench image's simulated `off_current_limit_a=0.200` gate;
* so the ON/OFF separation rule for any downstream feature is: drop the first frame of a driven block and the first two frames after the applied duty reaches 0, and say which frames were dropped.

## 8. A-W15-03 - reference check against an independent meter

Trusted independent meter available: **NO**.
Reported instead: *plausibility and internal consistency*.

* no calibration record for the PZEM-017 and none for the 50 A / 75 mV shunt exists in this repository (the shunt was seen in a photo only, SOURCE VERIFIED, never calibrated)
* V x I agreement: worst 0.099 W against a 0.18 W quantisation tolerance, 0 frames beyond tolerance in 4 committed sources
* energy agreement per source: W03-132b-off-envelope counter 0 Wh vs integral 0 Wh (COUNTER_WITHIN_QUANTISATION); W03-pzem-off-2026-10-20 counter 0 Wh vs integral 0 Wh (COUNTER_WITHIN_QUANTISATION); W04-H8C-box-600s counter 14 Wh vs integral 14.219 Wh (COUNTER_WITHIN_QUANTISATION)
* resolution limits: V 0.01 V, I 0.01 A, P 0.1 W, E 1.0 Wh - a 1 Wh counter and a 0.1 W register cannot resolve a short-run efficiency difference; only run-integral comparisons are meaningful

Certified calibration: **no**. Status label: **NEED_USER_ACTION** - one trusted reference meter (or a calibrated shunt channel) measured at several duty points against the PZEM, recorded in the same session.

## 9. What could not be computed, and why

* power factor / frequency features: the firmware never reads those registers, so no capture contains them;
* producer liveness counters (`power_beats`, `power_max_gap_ms`, `electrical_quality`): a delivered-schema concept that the bench image's line does not emit, so it exists only in the W05 host fixture;
* a duty-resolved electrical model from committed data alone: the ladder is local-bench only;
* stale-versus-fresh separation inside the committed CSV: its status and age columns are empty/absent;
* any calibration statement: no reference instrument, no shunt calibration.
